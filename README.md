# Navalrep: локальный монтаж вертикальных клипов

[![CPU tests](https://github.com/hatehse/navalrep/actions/workflows/ci.yml/badge.svg)](https://github.com/hatehse/navalrep/actions/workflows/ci.yml)

Python-проект для поиска эмоциональных концовок в испаноязычном видео и последовательного выпуска роликов 9:16. Расчётная машина: **NVIDIA RTX 4060 8 GB, 50 GB RAM**, Python **3.10–3.13**. Исходные видео обрабатываются на вашем ПК: внешние LLM, облачная транскрипция и отправка видео не используются.

Это эвристический поиск кандидатов, а не гарантия виральности: вопрос, громкий звук и склейка не всегда означают сюжетный клиффхэнгер. Просматривайте результат перед публикацией. Отражение, зум и изменение скорости — оформление; они не гарантируют обход Content ID. Используйте видео, на публикацию которого у вас есть права.

## Быстрый старт

Запускайте команды из корня проекта. Для **Windows** используйте PowerShell; для Linux — bash.

1. Установите NVIDIA-драйвер и FFmpeg с **h264_nvenc**, **libass** и FFprobe, добавьте их в `PATH`. Нужен шрифт DejaVu Sans (Linux: пакет `fonts-dejavu-core`) либо задайте установленный шрифт, например `Arial`, в `font_name`. Для актуального CTranslate2 нужны **CUDA 12, cuBLAS и cuDNN 9**. CUDA Toolkit для компиляции проекта не нужен. Совместимость драйвера и CUDA-версии wheel проверьте по официальным страницам [PyTorch](https://pytorch.org/get-started/locally/) и [Faster-Whisper](https://github.com/SYSTRAN/faster-whisper#gpu).

2. Создайте окружение:

```bash
python -m venv .venv
# Linux:
source .venv/bin/activate
# Windows PowerShell вместо source:
# .\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

3. Установите CUDA-сборку PyTorch по инструкции для своей ОС, например для поддерживаемого драйвером CUDA 12.8:

```bash
python -m pip install "torch>=2.5,<3" --index-url https://download.pytorch.org/whl/cu128
python -m pip install -e .
```

`pip install -e .` устанавливает `faster-whisper`, `scenedetect`, `opencv-python-headless`, `librosa`, `soundfile`, `numpy`, `scipy`, `torch`. Диапазоны совместимых версий указаны в `pyproject.toml`; это не фиксированный lockfile. PyTorch управляет своим кешем, а Faster-Whisper работает через CTranslate2: одного `torch.cuda.empty_cache()` для освобождения CT2 недостаточно.

При ошибках загрузки `libcublas.so.12` / `libcudnn.so.9` на Linux установите CUDA-библиотеки из pip:

```bash
python -m pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12>=9,<10"
```

Пайплайн сам добавляет найденные каталоги `nvidia/*/lib` и `torch/lib` в окружение **только дочернего процесса Whisper**. На Windows поддерживаются `torch/lib`, найденные `nvidia/*/bin` и системные DLL из `PATH`; при необходимости установите cuDNN 9 и cuBLAS 12 по инструкции NVIDIA. Не отключайте проверку TLS или контроль целостности пакетов.

4. Один раз, **с интернетом**, скачайте модель (несколько GB, заложите место для кеша и модели):

```bash
python main_pipeline.py download-model --destination models/large-v3
```

Команда получает только модель `Systran/faster-whisper-large-v3` с Hugging Face, видео не передаёт. Загрузку также можно сделать на другом компьютере и перенести **весь** каталог модели. После этого интернет для обработки не нужен. При ограниченной сети загрузке могут требоваться `huggingface.co` и его актуальные CDN-домены; проще подготовить модель на машине с доступом.

5. Скопируйте `config.example.json` в `config.json`, заполните `telegram_url`, если нужен прямой переход, и положите `episode.mp4` в `input/`:

```bash
python main_pipeline.py --config config.json doctor
python main_pipeline.py --config config.json run
# Один файл или несколько конкретных файлов:
python main_pipeline.py --config config.json run --input input/episode.mp4
```

Глобальные опции `--config` и `--verbose` ставятся **перед** `run`/`doctor`. Альтернативные точки входа: `navalrep` или `python -m navalrep`.

`doctor` проверяет Python-зависимости, локальную модель, фильтр субтитров и **реальное кодирование трёх кадров NVENC**. Наличие названия кодировщика в FFmpeg само по себе не доказывает наличие GPU/драйвера. `--no-encode-test` пропускает только пробное кодирование. `doctor` не запускает полноценную транскрипцию: совместимость CTranslate2/CUDA окончательно проверяется на первом файле. При сбое не происходит скрытого перехода на CPU или другую модель.

## Структура

```text
main_pipeline.py          # простой вход
config.example.json      # настройки без секретов
pyproject.toml           # установка и зависимости
src/navalrep/
  analysis.py            # сцены, WAV, отдельный процесс Whisper, RMS
  selection.py           # рейтинг, границы, длительность, дедупликация
  render.py              # SRT, libass, FFmpeg/NVENC
  pipeline.py            # последовательные этапы и отчёты
  config.py              # проверка конфигурации
  doctor.py              # проверка машины
input/                   # исходники; никогда не удаляются
output/                  # готовые видео, субтитры, описания, отчёты
temp/                    # только автоматически созданные рабочие каталоги
models/large-v3/          # локальная модель; не включена в Git
tests/                   # стандартный unittest
```

`input/`, `output/`, `temp/`, модели, виртуальное окружение, логи и личные `config.json`/`.env` исключены из Git. В репозитории хранится `config.example.json`. Пути в JSON считаются относительно **текущего рабочего каталога**, а не расположения JSON. Имена файлов могут содержать пробелы, апострофы и испанские символы.

## Что происходит с одним эпизодом

1. **CPU:** PySceneDetect `ContentDetector` ищет монтажные склейки. Порог `scene_threshold=27` и минимальный промежуток 15 кадров настраиваются. Склейка — граница монтажного плана, не обязательно завершение сюжетной сцены. Плавные переходы этот детектор может пропускать.
2. **CPU:** FFmpeg извлекает только первую аудиодорожку в PCM mono 16 kHz. Для сериалов с несколькими языками заранее выберите испанскую дорожку; автоматического выбора по метаданным нет.
3. **GPU:** отдельный процесс `spawn` загружает `large-v3`, `cuda`, `float16`, один worker, испанский язык, VAD и таймкоды слов. Генератор Faster-Whisper полностью читается. Затем закрывается генератор, выгружается CTranslate2-модель, удаляются ссылки, вызываются GC и `torch.cuda.empty_cache()`, процесс **завершается и join-ится**. Только после этого начинается следующий этап. Для долгого эпизода увеличьте `timeout` (по умолчанию 4 часа на внешнюю операцию).
4. **CPU:** librosa RMS ищет резкие изменения громкости относительно локальной медианы и предыдущего кадра RMS. Аудио читается блоками по 30 секунд; полная PCM-дорожка не удерживается в RAM на этом этапе. Порог `audio_peak_db=7` — скачок в dB, не абсолютная громкость. Музыка и шум тоже могут дать пик.
5. Поиск `?`, `!`, фраз `¿Quién es?`, `¡No puede ser!` и других триггеров без учёта регистра/акцентов. Сигналы должны находиться в последних `peak_lookback=5` секундах перед склейкой. Тихий хвост длиннее `max_silence_after_peak=2` секунд отбрасывается. Сильные независимые сигналы повышают рейтинг, пересекающиеся нарезки подавляются. Если кандидатов нет, случайные ролики не создаются.
6. **Длительность после 1.04×:** допустимый исходный интервал — **36.4–57.2 секунды**, чтобы результат был **35–55 секунд**. Конец всегда на найденной склейке или конце файла. Начало также выбирается на склейке, если возможно; для короткой сцены захватываются предыдущие планы. Если ни одна начальная склейка не даёт разрешённую длину, режется только начальный контекст: это отмечается `context_start_trimmed_for_duration`. Одновременно гарантировать обе границы на склейках и точный диапазон длины для любого видео невозможно.
7. **NVENC:** отражение (`mirror`), зум (`zoom`), центральный кроп 1080×1920, 30 FPS, видео `setpts/1.04`, аудио `atempo=1.04` без изменения тональности. Декодирование, масштабирование и libass работают на CPU; GPU кодирует H.264. Все клипы и эпизоды обрабатываются строго последовательно. Ускорение на основе optical flow и GPU-декодирование намеренно не используются.
8. Субтитры на основе слов группируются до 6 слов/3.5 сек, обрезаются по клипу и переводятся на ускоренную шкалу времени. Выходной `.srt` сохраняется; временный ASS задаёт точный размер холста. Жёлтый жирный текст с чёрной обводкой размещается в центре. Если речи нет, субтитры пустые. Центральный кроп не отслеживает лица и может срезать персонажа: для этого потребовался бы отдельный модуль рефрейминга.
9. FFprobe проверяет итоговую длительность; выход за 35–55 секунд считается ошибкой. Видеодлительность округляется вниз до полного кадра (не более одного кадра потери в конце). Исходные метаданные и главы удаляются. Технические поля MP4, необходимые декодеру, остаются; ложные сведения об устройстве съёмки не добавляются.

Закройте другие приложения, использующие VRAM. `large-v3/float16` рассчитан на 8 GB, но свободная память зависит от драйвера и других процессов. При OOM файл получает ошибку, модельный процесс завершается, обработка переходит к следующему эпизоду; уменьшите `beam_size` до 1, если нужно сохранить именно `large-v3/float16`. Одновременный запуск нескольких экземпляров проекта не поддерживается этой гарантией последовательности.

## Результаты и ошибки

Для каждого эпизода создаётся уникальный каталог, поэтому повторный запуск не затирает прошлые результаты:

```text
output/episode_<id>/
  clip_01.mp4             # готовое 9:16-видео
  clip_01.srt             # уже с учётом 1.04×
  clip_01.txt             # мексиканская разговорная подпись + CTA + 5 хэштегов
  analysis.json           # транскрипция, пики, склейки, рейтинг и настройки
  report.json             # успешные клипы и точные ошибки этапов
output/pipeline.log
output/run_<id>.json      # итог всей очереди
```

Описания генерируются локальными шаблонами, без LLM и выдуманных сведений о сюжете. Без `telegram_url` CTA ссылается на Telegram в био. **Актуальную трендовость офлайн проверить нельзя**: пять хэштегов редактируются в JSON; значения по умолчанию тематические, а не подтверждённые тренды.

Временные WAV/ASS/сырые результаты удаляются через `TemporaryDirectory` при успехе, исключении и обычном Ctrl+C. Не выполняется массовое удаление `temp/*`: чужие файлы сохраняются. При принудительном завершении ОС/отключении питания могут остаться каталоги `episode-*` или `.render-*`; удаляйте только заведомо неиспользуемые рабочие каталоги. Постоянные SRT, транскрипция и отчёты — полезные результаты, не мусор.

Ошибка анализа пропускает эпизод; ошибка одного рендера пропускает этот клип, остальные продолжаются. Код выхода: `0` — все эпизоды дали клипы без ошибок, `1` — ошибка/частичный результат/нет кандидатов, `130` — Ctrl+C. Статусы `failed`, `partial`, `no_candidates`, `ok` различаются в отчётах. Отсутствие кандидатов обычно означает, что нужно проверить исходник и пороги, а не проблему GPU.

## Проверки разработки

```bash
python -m unittest discover -s tests -v
python -m compileall -q main_pipeline.py src tests
```

GitHub Actions выполняет CPU-проверки на Ubuntu с Python 3.10, 3.12 и 3.13 после push и при открытии pull request. Команда `python scripts/run_ci.py` запускает тот же набор тестов и считает пропуски ошибкой, чтобы отсутствие FFmpeg или других зависимостей не давало ложный успех. CI не загружает модель и не подтверждает работу CUDA/NVENC на целевом ПК. Правила участия и подготовки изменений — в [CONTRIBUTING.md](CONTRIBUTING.md).

Тесты покрывают границы и рейтинг, выходную длительность, SRT, позицию текста в кадре, ошибки и очистку. Сквозной CPU-тест соединяет реальные этапы анализа и монтажа с заранее заданной транскрипцией. CPU-интеграционные тесты используют синтетические видео/аудио; тестовый адаптер NVENC → libx264 проверяет **фильтры и контейнер**, а не GPU. При отсутствии FFmpeg/CPU-библиотек соответствующие тесты помечаются skipped. Настоящие Whisper large-v3 и h264_nvenc требуют локальных модели и NVIDIA GPU: для приёмки на RTX 4060 запустите `doctor`, затем обработайте реальный испанский эпизод и проверьте `report.json`, длительности, субтитры и визуальную концовку клипов.
